About This Guide

A step-by-step guide to querying Agentforce Flex Credit consumption from Data Cloud DLOs and building role-appropriate reports and dashboards in Salesforce.

PACCAR has deployed Agentforce agents to production and is actively consuming Flex Credits. This guide gives every team - developers, admins, managers, and finance - a single reference for understanding what data is available, how to query it safely, and how to build the right report or dashboard for their role without triggering security alerts or exposing contract-sensitive data.

Goal 1
Query Flex Credit consumption data directly from Data Cloud using SQL
Goal 2
Build a developer-safe consumption report shareable without elevated permissions
Goal 3
Build a manager dashboard with burn rate, remaining balance, and projected exhaustion

What Are DLOs?

DLOs (Data Lake Objects) are Salesforce-managed tables inside Data Cloud that store your Agentforce Flex Credit usage data. Think of them as the raw ledger behind everything you see in the Digital Wallet.

When you deploy an agent to production, every interaction is recorded as an event in these tables. By querying DLOs directly, you can build custom reports with any filters, groupings, or date ranges you need - without relying on the out-of-the-box Digital Wallet UI.

Where to Run These Queries
Go to Data Cloud → Query Editor in your production org. DLO queries do not run in Developer Console, Workbench, or sandboxes. Data is tracked across all environments but is only visible through production.

Each DLO serves a different reporting purpose and has a different access sensitivity. Use this table to decide which object you need before writing your query.

__dll Suffix Required
In Data Cloud Query Editor, every DLO table name needs the __dll suffix - e.g. TenantEnrichedUsageEvent__dll. Without it, the query returns "table not found."

Platform Rules - Read Before Querying

  • Query Editor only. Go to Data Cloud → Query Editor using the default Data Space. This is SQL, not standard SOQL.
  • Production org only. You cannot view consumption data from a sandbox.
  • Always run discovery first. Column names can vary between orgs. Run SELECT * FROM <table>__dll LIMIT 5 before any filtered query.
  • Data retention was observed at 730 days. Data retention was observed at 730 days in this org as of testing (September 2026). Retention windows are configurable per org/data space - confirm your org's current setting in Data Cloud Setup rather than treating this as a fixed platform limit.
Critical - cardname__c Does NOT Exist on TDEC

Developer Consumption Query
Daily credit totals from TEUE - safe for developer-level access
Always Exclude SpeechFoundations_Translation
Without this filter, totals will be higher than the Digital Wallet shows. Always include usagetypedevelopername__c <> 'SpeechFoundations_Translation'.
SQL · Data Cloud Query Editor - Confirmed Working
-- Developer Consumption: Daily totals by usage type
SELECT
    CAST(eventtime__c AS DATE)     AS usage_date,
    usagetypedevelopername__c      AS usage_type,
    SUM(unitsconsumed__c)          AS total_credits,
    COUNT(*)                       AS event_count
FROM TenantEnrichedUsageEvent__dll
WHERE usagetypedevelopername__c <> 'SpeechFoundations_Translation'
-- AND usagebusinessenvtype__c = 'production'
-- AND eventtime__c >= CURRENT_DATE - INTERVAL '90' DAY
GROUP BY CAST(eventtime__c AS DATE), usagetypedevelopername__c
ORDER BY usage_date DESC
LIMIT 100;

Manager Entitlement Query
Daily burn rate - allocation pulled dynamically from TET · Manager access required
Manager / Admin Access Required
This query accesses TDEC which contains your purchased credit allocation and remaining balance. Restrict to manager and admin users only.

Because TDEC tracks daily consumption logs (not a running allocation balance), the allocated credit limit is pulled dynamically from TenantEntitlementTransaction__dll using a CTE - no hardcoded values needed.

Option 1 - Dynamic Subquery (Global Total)

SQL · Option 1 - Global Total
WITH total_allocation AS (
    SELECT COALESCE(SUM(quantity__c), 0) AS allocated_credits
    FROM TenantEntitlementTransaction__dll
),
base_usage AS (
    SELECT
        utilizationdate__c   AS report_date,
        unitsconsumed__c     AS consumed_credits
    FROM TenantDailyEntitlementConsumption__dll
    WHERE utilizationdate__c >= CURRENT_DATE - INTERVAL '90' DAY
      AND unitsconsumed__c > 0
)
SELECT
    u.report_date, a.allocated_credits, u.consumed_credits,
    (a.allocated_credits - u.consumed_credits)                            AS remaining_credits,
    ROUND((u.consumed_credits / NULLIF(a.allocated_credits, 0)) * 100, 1) AS pct_consumed
FROM base_usage u
CROSS JOIN total_allocation a
ORDER BY u.report_date DESC;

Option 2 - Join by Specific Credit Card Type

SQL · Option 2 - By Card Type
WITH card_allocations AS (
    SELECT entitlementcarddefdevlname__c AS card_name, SUM(quantity__c) AS allocated_credits
    FROM TenantEntitlementTransaction__dll
    GROUP BY entitlementcarddefdevlname__c
)
SELECT
    c.utilizationdate__c                                                   AS report_date,
    a.allocated_credits,
    c.unitsconsumed__c                                                     AS consumed_credits,
    (a.allocated_credits - c.unitsconsumed__c)                             AS remaining_credits,
    ROUND((c.unitsconsumed__c / NULLIF(a.allocated_credits, 0)) * 100, 1)  AS pct_consumed
FROM TenantDailyEntitlementConsumption__dll c
JOIN card_allocations a ON c.carddefinitiondevelopername__c = a.card_name
WHERE c.utilizationdate__c >= CURRENT_DATE - INTERVAL '90' DAY
  AND c.unitsconsumed__c > 0
ORDER BY c.utilizationdate__c DESC;

Build the Report in Report Builder
Turn a verified query into a shareable Salesforce report
  1. Go to Reports tab → New Report.

    From the App Launcher in your production org, navigate to the Reports tab and click New Report.

  2. Select Report Type: Data Cloud.

    In the category picker, scroll to Data Cloud and choose it as your report type.

  3. Choose your primary object.

    For the developer report: select TenantEnrichedUsageEvent. For the manager report: select TenantDailyEntitlementConsumption.

  4. Add fields from the field picker.

    Drag in the fields confirmed during discovery: date field, usage type, credits, and calculated columns.

  5. Set your filters.

    For TEUE: usagetypedevelopername__c != SpeechFoundations_Translation. For TDEC: add a date range filter using utilizationdate__c.

  6. Group and summarize.

    Group rows by date and usage type. Add a SUM summary on the credits field to get daily totals.

  7. Run and verify.

    Confirm totals match what you saw in Query Editor.

  8. Save to a shared folder.

    Click Save → name the report → choose the correct folder. To share with non-admin users, the folder only needs Run Reports permission.

No Elevated Permissions Needed for Developer Report
The developer report (TEUE-based) can be shared with any user via Run Reports permission - no Digital Wallet access, View All Data, or elevated admin permissions required.

Security Boundary - What's Included vs Excluded

This report deliberately includes only consumption data and excludes all contract and billing information. Keeping this boundary intact is what makes the report safe to share broadly.

Developer Report Security Boundary - TenantEnrichedUsageEvent Only
✓ Included in This Report
  • Daily credit consumption totals
  • Usage type (feature type breakdown)
  • Event count (number of interactions)
  • Date range filtering
  • Production vs sandbox environment filter

Why This Solves the Access Problem
The Digital Wallet requires elevated permissions that trigger Security Center alerts. A report from TenantEnrichedUsageEvent contains only consumption fields - not contract data - so it can be shared via a standard report folder with just the Run Reports permission. No elevated access required.

Troubleshooting

Error: unknown column 'agentid__c'
Fix: The correct agent identifier is rootresourceidorapiname__c, not agentid__c.
Error: unknown column 'credits__c'
Fix: The correct credit amount field on TEUE is unitsconsumed__c, not credits__c.
Error: unknown column 'environment__c'
Fix: The correct field is usagebusinessenvtype__c and the value is 'production' (lowercase).
My totals don't match the Digital Wallet
Fix: Ensure your WHERE clause includes usagetypedevelopername__c <> 'SpeechFoundations_Translation'. Note: a Feb 2026 Flow/Prompt Builder undercounting bug may cause minor discrepancies for events from that period.
Query returns 0 rows
Fix: (1) Confirm you are in the production org. (2) Confirm at least one agent is deployed to production. (3) Run SELECT * FROM TenantEnrichedUsageEvent__dll LIMIT 5 with no WHERE clause.
userid__c returns NULL for all rows
Fix: Expected for Service Agents. Per-user attribution is only available for Employee Agents.

Burn Rate Query
% of allocation consumed per day - confirmed working

Pulls the contracted allocation dynamically from TenantEntitlementTransaction__dll via a CTE - no hardcoded values. Uses a CROSS JOIN to attach the total allocation to every daily row before calculating burn rate.

Verified Working Query
Allocation is pulled live from TenantEntitlementTransaction__dll using COALESCE(SUM(quantity__c), 0) - stays accurate as your contract is renewed or topped up.
SQL · Data Cloud Query Editor - Verified
WITH total_allocation AS (
    -- Dynamically calculate total contracted allocation
    SELECT COALESCE(SUM(quantity__c), 0) AS allocated_credits
    FROM TenantEntitlementTransaction__dll
),
base_usage AS (
    SELECT
        c.utilizationdate__c                                  AS report_date,
        c.unitsconsumed__c                                    AS consumed_credits,
        a.allocated_credits
    FROM TenantDailyEntitlementConsumption__dll c
    CROSS JOIN total_allocation a
    WHERE c.utilizationdate__c >= CURRENT_DATE - INTERVAL '90' DAY
      AND c.unitsconsumed__c > 0
)
SELECT
    report_date,
    allocated_credits,
    consumed_credits,
    (allocated_credits - consumed_credits)                             AS remaining_credits,
    ROUND((consumed_credits / NULLIF(allocated_credits, 0)) * 100, 1) AS pct_consumed
FROM base_usage
ORDER BY report_date DESC;

4
Projected Exhaustion Query
When will credits run out at the current burn rate?
Exhaustion Formula
Texhaust = today + (remaining_credits ÷ avg_daily_burn) days
The 30-day window smooths weekday/weekend variance. Use 7-day rolling average if consumption has strong weekly cycles.

),
latest_usage AS (
    SELECT

Query C - Projected Exhaustion Date (Single Combined Query)

Combines cumulative remaining balance and 30-day average burn using two CTEs with CROSS JOIN. Returns one row with today's date, remaining credits, avg daily burn, and days until exhaustion. Confirmed working.

SQL · Step C - Projected Exhaustion - Verified
WITH total_allocation AS (
    SELECT COALESCE(SUM(quantity__c), 0) AS total_credits
    FROM TenantEntitlementTransaction__dll
),
total_consumed AS (
    SELECT COALESCE(SUM(unitsconsumed__c), 0) AS total_consumed
    FROM TenantDailyEntitlementConsumption__dll
),
daily_burn AS (
    SELECT AVG(unitsconsumed__c) AS avg_daily_burn
    FROM TenantDailyEntitlementConsumption__dll
    WHERE utilizationdate__c >= CURRENT_DATE - INTERVAL '30' DAY
)
SELECT
    CURRENT_DATE                                                                AS today,
    (a.total_credits - c.total_consumed)                                       AS remaining_credits,
    ROUND(b.avg_daily_burn, 1)                                                 AS avg_daily_burn,
    FLOOR((a.total_credits - c.total_consumed) / NULLIF(b.avg_daily_burn, 0))  AS days_until_exhaustion
FROM total_allocation a
CROSS JOIN total_consumed c
CROSS JOIN daily_burn b;

Manager Entitlement Query - Dynamic Allocation
Allocation pulled live from TenantEntitlementTransaction - no hardcoded values

Because TDEC tracks daily consumption logs (not a running allocation balance), the credit limit is pulled dynamically from TET using a CTE.

Option 1 - Dynamic Global Total

Use when your org has a single credit pool.

SQL · Option 1 - Global Total
WITH total_allocation AS (
    SELECT COALESCE(SUM(quantity__c), 0) AS allocated_credits
    FROM TenantEntitlementTransaction__dll
),
base_usage AS (
    SELECT
        utilizationdate__c   AS report_date,
        unitsconsumed__c     AS consumed_credits
    FROM TenantDailyEntitlementConsumption__dll
    WHERE utilizationdate__c >= CURRENT_DATE - INTERVAL '90' DAY
      AND unitsconsumed__c > 0
)
SELECT
    u.report_date, a.allocated_credits, u.consumed_credits,
    (a.allocated_credits - u.consumed_credits)                            AS remaining_credits,
    ROUND((u.consumed_credits / NULLIF(a.allocated_credits, 0)) * 100, 1) AS pct_consumed
FROM base_usage u
CROSS JOIN total_allocation a
ORDER BY u.report_date DESC;

Option 2 - Join by Specific Credit Card Type

Use when your org has multiple credit types. Join key: TET.entitlementcarddefdevlname__c = TDEC.carddefinitiondevelopername__c.

SQL · Option 2 - By Card Type
WITH card_allocations AS (
    SELECT entitlementcarddefdevlname__c AS card_name, SUM(quantity__c) AS allocated_credits
    FROM TenantEntitlementTransaction__dll
    GROUP BY entitlementcarddefdevlname__c
)
SELECT
    c.utilizationdate__c                                                   AS report_date,
    a.allocated_credits,
    c.unitsconsumed__c                                                     AS consumed_credits,
    (a.allocated_credits - c.unitsconsumed__c)                             AS remaining_credits,
    ROUND((c.unitsconsumed__c / NULLIF(a.allocated_credits, 0)) * 100, 1)  AS pct_consumed
FROM TenantDailyEntitlementConsumption__dll c
JOIN card_allocations a ON c.carddefinitiondevelopername__c = a.card_name
WHERE c.utilizationdate__c >= CURRENT_DATE - INTERVAL '90' DAY
  AND c.unitsconsumed__c > 0
ORDER BY c.utilizationdate__c DESC;
Which Option Should I Use?
Option 1 - single credit pool, simple global total. Option 2 - multiple credit card types, each calculated against its own allocation limit.

Required Permission Sets for Manager Dashboard

Confirm Current Labels
Permission set names below reflect this org as observed in September 2026. Exact labels can vary by org edition/release - confirm current names in Setup → Permission Sets before assigning.
  • View Consumption
    Read access to the Digital Wallet, consumption cards, and out-of-the-box dashboards.
  • View Consumption Tags
    Required if your org uses custom consumption tags.
  • Data Cloud Data Access
    Read access to Data Cloud objects and DLO schemas. Required to build and run custom reports against entitlement DLOs.
  • Manage Flow / Run Flows
    Required only if this user also manages Consumption Threshold Alert flows. Optional for read-only dashboard viewers.

Governance Recommendations

  • Create a dedicated Public Group (e.g., "Flex Credit Dashboard Viewers") for all manager and finance users who need access.
  • Share the manager report folder with this Public Group only - never with "All Internal Users."
  • Audit access quarterly to ensure only authorized stakeholders have visibility into contract and budget data.
  • Never combine developer and manager reports in the same folder - separate folders, separate sharing rules.
  • When onboarding new finance or manager users, assign permission sets explicitly - do not rely on profile-level defaults.
Never Merge These Two Reports
The developer consumption report (TEUE) and the manager entitlement dashboard (TDEC + TET) must remain in separate folders with separate sharing rules. Merging them would expose contract terms to developers - a data governance violation.
