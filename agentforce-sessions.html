Turn on Sessions & Intents

Sessions & Intents ships switched off and sits behind Data Cloud. Nothing in your agent's own configuration turns it on. Here are the prerequisites and the steps, nothing else.

Agentforce Data 360 Session Tracing ~30 min plus batch wait

01 Prerequisites

Requirement Why
Data 360 provisioned All trace data lands in Data Cloud objects. Without it, Salesforce hides the monitoring setup node entirely.
Einstein turned on Required before any audit and monitoring features appear.
At least one active agent A draft agent produces no traffic to trace.
SSOT package 1.128+ The session tracing data model ships inside this package.
Developer Edition

A plain Developer Edition org has no Data Cloud, so none of this works. Use an Agentforce-enabled Developer Edition org, which comes with Data 360 already provisioned.

02 Setup steps

  1. Confirm Data Cloud is provisioned

    Setup, Quick Find, Data Cloud. If nothing comes up, stop here. Every step below depends on this one.

  2. Check the SSOT package version

    Setup, Quick Find, Installed Packages. Find Salesforce Standard Data Model, namespace ssot. You need 1.128 or higher. Salesforce upgrades this on its own schedule, so you cannot force it.

  3. Flip both toggles, not just the first

    Setup, Quick Find, Einstein Audit, Analytics, and Monitoring Setup. Turn on all three:

    • Agentforce Session Tracing, the capture layer. Enabling it provisions the data model entities.
    • Agent Optimization, the layer that mines traces into sessions and intents. Skipping this is the single most common reason the screen stays empty.
    • Audit and Feedback, captures the thumbs up and thumbs down signals from the chat panel.
    If you cannot find the node

    Search Quick Find for a fragment instead: Feedback, Audit, Tracing, or Generative. If nothing turns up, you are hitting the Data Cloud prerequisite, since Salesforce hides the node rather than greying it out.

  4. Install Agent Analytics

    Setup, Quick Find, Agent Analytics. Open the menu on Employee Agent Analytics or Service Agent Analytics, whichever matches your agent, and click Install.

  5. Assign permissions

    For whoever does the setup: Data Cloud Admin and CRM Analytics Plus Admin.

    For anyone who only reads sessions: Data Cloud Data Aware Specialist, plus read access to the ssot__ objects such as AIAgentSession.

    Multiple data spaces

    Grant access in each data space separately. Objects in non-default spaces carry a prefix, following <DataSpacePrefix>_<ObjectName>.

  6. Confirm the agent is active

    In Agentforce Builder the version should read Active and the button should say Deactivate, not Activate.

  7. Run real conversations

    Use the deployed channel, not the Preview panel in Builder. There is no backfill, so anything from before you enabled tracing is gone.

  8. Verify at the data layer, then wait

    Data Cloud, Data Explorer, open AIAgentSession. Rows present means tracing works and only the display layer is behind, so wait. No rows means tracing is not capturing, so go back to steps 2 and 3.

    Sessions & Intents is batch processed. On a freshly provisioned org the first run can take several hours.

03 The two empty states

They look similar and mean different things. Read the wording.

Read the transition as progress

Moving from the first message to the second means your provisioning and toggles worked. If you are still on the first, do not go hunting for missing conversations.

04 Checklist

  • Data Cloud provisioned, Einstein on
  • SSOT package 1.128 or higher
  • Session Tracing on, Agent Optimization on, Audit and Feedback on
  • Agent Analytics installed for your agent type
  • Permission sets assigned, per data space
  • Agent active, real conversations through a real channel
  • AIAgentSession checked in Data Explorer
  • Wait for batch, check again tomorrow
Two things that catch everyone

No backfill, so turn tracing on before your pilot rather than after. And observability is a licensing conversation, since session tracing and Agent Analytics both sit on Data 360.

Salesforce renames these setup nodes fairly often. If a label does not match what you see, search Quick Find for the distinctive fragment rather than the full phrase.
